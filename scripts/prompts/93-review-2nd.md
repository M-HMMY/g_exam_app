**1 巡目の指摘を反映したあとに掛けるレビューです。**

**★ このひな形は 8 つめ（`kouatsugas_otsu_exam_app`）で初めて作り、系譜の全リポジトリへ配りました。**

**なぜ要るか。**[docs/handover.md](../../docs/handover.md) §4 に実績があります。

| 回 | 出たもの |
| --- | --- |
| 7 つめ（危険物 甲種）で 2 巡目を回した | **1 巡目の修正そのものが新しい誤りを作っていた**箇所が見つかった |
| 8 つめ（高圧ガス 乙種）で最後まで回した | **43 件。うち 9 件が「1 巡目の直しが作った新しい誤り」、34 件が直し漏れ** |

**1 巡目とは見るところが違います。**「全体が正しいか」ではなく、
**「この変更が、何かを壊していないか」**を見てください。

**`--sandbox read-only` で走らせてください。**指摘だけさせて、直すのは依頼した側です。

## 渡すもの

- **差分ファイル**（`git diff <1 巡目の前> HEAD -- <対象>` の出力）
- **変更後のファイル**（リポジトリの現在の中身）
- **`CLAUDE.md`**、**数値の台帳があればそれ**

## 何を見るか（この順に）

### 1. ★ その変更が、新しい誤りを作っていないか（最優先）

**足した条件が、別の正しいことを否定していないか。**

- 「理想気体なら」と限定したせいで、実在気体でも成り立つ話まで狭めていないか
- 「原則として」と付けたせいで、例外がないものまで曖昧にしていないか
- **足した文が、同じ節の別の段落と矛盾していないか**

**8 つめで実際に出た 9 件のうち、分かりやすいもの。**

| 直したつもりが | 何が起きたか |
| --- | --- |
| 見出しを「非 SI 単位」から「SI 基本単位でない単位は式へ入れる前に直す」に広げた | **Pa・J・W まで変換が要ることになった。**同じ節が自分で Pa を式に入れている |
| 断熱変化に「ゆっくり（可逆的に）」を足した | **摩擦があれば、どれだけゆっくりでも不可逆** |
| ウィジェットの判定基準だけ厳しくした | **教本と台帳が古い基準のままで、自分で食い違いを作った** |
| 解説に具体例を書き足した | **その節が挙げている代表例と違うものを書いていた** |

### 2. ★ 直し漏れ — 同じ主張の別の居場所

**これがいちばん多く出ます。**8 つめでは **43 件のうち 34 件**がこの型でした。

**★ 1 つの主張は、1 つの節の中に 6 つの居場所を持ちます。**

```
本文 ／ 表 ／ 試験のポイント ／ よくある勘違い ／ この節のまとめ ／ 一問一答
```

**さらにその外側に、確認問題・計算ドリル・体験ウィジェット・画面の文言・執筆プロンプトがあります。**

**★ 執筆プロンプトを直し忘れると、書き直したときに全部戻ります。**
8 つめでは、直したはずの言い切りが `scripts/prompts/` に **7 か所**残っていました。

**数える道具があります。**

```
node scripts/echoes.mjs 安全率          … その語がどこに何回あるかを、居場所つきで出す
node scripts/echoes.mjs 爆発範囲 まん中  … すべてを含む行だけ
node scripts/terms.mjs                  … 確認問題が使っていて、教本に無い語を挙げる
```

**★ もっとも重いのは、教本が確認問題と正面から反対のことを言っている形です。**
1 巡目の指摘は確認問題に対して出るので、**直す側が教本を見ないまま終わります。**
8 つめでは 3 件出ました。たとえば教本は「元弁を閉めてはいけない」と言い切っていたのに、
確認問題の解説は条文のただし書（「修理又は清掃のため特に必要な場合を除き」）を引いていました。
**教本を信じると、正しい記述を誤りだと判定します。**

### 3. ★ 確認問題を直した場合

- **`answer` が、直した後の記述の正誤と合っているか**
- **解説の「〜は誤り」が、直した後の記述と合っているか**
- **選択肢の中に、直した後の正解が実際にあるか**
- **足した記述が、その問の `sectionId` の節に裏付けを持っているか。**
  **教本が使っていない語を、確認問題に持ち込んでいないか**
- 記述の長さが不ぞろいになり、**読まずに選べる**ようになっていないか

### 4. ★ 教本を直した場合

- **節の字数**が、そのアプリの決めた範囲から外れていないか
- **図の要素数の決まり**（`compare` の偶数、`matrix` のセル数）が保たれているか
- **`**` の開きと閉じが同じ行にある**か
- **張ったリンクの節 ID が実在する**か

### 5. ★ 指摘を採らなかった判断が妥当か

**1 巡目の指摘のうち、依頼した側が採らなかったものがあります。**
その理由がコミットメッセージに書いてあれば、**その理由が成り立つか**を見てください。

## 報告の形

```
### 【重さ】 対象 — 一行の要約

- **どう直したか**：（差分のどの行か）
- **何が問題か**：（★ 新しい誤りか、直し漏れか、どちらかを明示する）
- **正しくは**：
- **根拠**：（一次資料、またはファイル名と行）
```

| 重さ | 何か |
| --- | --- |
| **重** | **直したことで新しい誤りができた。**または、直した主張と正面から矛盾する記述が残っている |
| **中** | 直し漏れ。1 か所だけ古い言い方が残っている |
| **軽** | 言い回し、長さ、リンク |

**最後に、次の 4 つを必ず書いてください。**

1. **差分のすべての変更を見たか**（見ていないものは挙げる）
2. **確かめたが問題が無かった変更**
3. **資料からは確かめられなかったもの**
4. **★ あなたが自信を持てない指摘**

**「1 巡目の修正はすべて妥当です」だけの報告は受け付けません。**
**4 が空の報告も受け付けません。**
